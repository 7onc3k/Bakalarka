## Ablace — nový design (literature-driven)

### Přeformulováno z sekčních na rozpor-based ablace:
- Starý design: Ablace A = bez Constraints, Ablace B = bez PQ
- Nový design: Ablace A = bez verifikačních kroků, Ablace B = bez PQ

### Ablace A: bez verifikačních kroků
- **Rozpor**: Lulla (verbose step-by-step negativní) vs naše data (checks = průlom r3)
- **Odebráno**: git log --oneline -3, tsc --noEmit, npx eslint z Process
- **Zůstává**: workflow struktura (issue→branch→test→implement→PR)
- **AGENTS.md**: experiments/infra/inputs/AGENTS-ablace-a.md

### Ablace B: bez Package Quality
- **Rozpor**: Lulla (architektura nejúčinnější) vs Gloaguen (marginal) vs naše r5 (modulární bez workflow)
- **Odebráno**: celá sekce Package Quality
- **Zůstává**: Process + Constraints
- **AGENTS.md**: experiments/infra/inputs/AGENTS-ablace-b.md

### Plán runů: 4 runy přes noc
- 2× ablace A
- 2× ablace B

### 7 rozporů identifikovaných v literatuře (z nich top 3 vybrány)
1. Verifikační kroky vs workflow → Ablace A
2. Architektura z instrukcí vs z tréninku → Ablace B
3. Nondeterminismus v agentech → pokryto r3/r4/r5 variancí
4. AGENTS.md pomáhá vs nepomáhá (Lulla vs Gloaguen)
5. Exclusion constraints efektivita (Mao vs naše data)
6. Curated vs self-generated (Li/SkillsBench)
7. Scaffolding vs model capability (Confucius)

### Nepoužité zdroje k doplnění do thesis
- Confucius (Wong 2026) — scaffolding > model, v sources ale necitovaný
- ACE (agentic context engineering) — iterativní error correction
- Chatlatanagulchai (agent-readmes-2025) — co developeři do context files píší
