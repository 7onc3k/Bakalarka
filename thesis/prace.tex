\def\Abstrakt{%
AI coding agenti dokáží generovat funkční kód, ale bez vhodných instrukcí
nedodržují softwarově-inženýrské praktiky. Existující benchmarky měří pouze
výsledek (vyřešil agent úkol?), nikoli kvalitu procesu ani kódu.
Formalizovaný postup pro návrh a~vyhodnocování instrukcí dosud chybí.
%
Práce si klade tři cíle: (1)~navrhnout sadu metrik měřících proces, kvalitu
a~efektivitu práce agenta; (2)~demonstrovat iterativní postup návrhu instrukcí
řízený těmito metrikami; (3)~ablacemi prozkoumat, které složky instrukční
sady přispívají k~měřenému chování agenta a~které jsou redundantní.
%
Sadu metrik a~postup ověřujeme na případové studii systému upomínek
faktur. Agent (model MiniMax-M2.5 prostřednictvím nástroje OpenCode) prošel pěti
pilotními iteracemi a~dvěma ablacemi, každou ve dvou nezávislých bězích.
Chování bylo měřeno 19~metrikami
ve třech kategoriích: procesní (P), produktové~(Q) a~efektivita~(E).
%
Metriky zachytily, že iterativní úpravy instrukcí zlepšily dodržování
pracovního postupu, ale ne monotónně. Nejlepší pilotní běh dosáhl
plného splnění procesních metrik P1--P5 a~zvýšil počet projitých
referenčních testů z~39/42 na~41/42. Analýza odhalila vzorec vývoje
instrukcí: obecné pravidlo $\to$ konkrétní příkaz $\to$ verifikační krok.
Ablace ukázaly, že verifikační kroky nejsou redundantní; jejich odebrání
zhoršilo funkční korektnost i~automatizované metriky kvality kódu.
Sekce kódových konvencí byla pro automatizované metriky převážně
redundantní, ale ovlivňovala designovou kvalitu hodnocenou
LLM-as-judge. Výsledky současně ukázaly, že procesní compliance je
výrazně citlivá na nedeterminismus modelu.
%
Přenositelným přínosem jsou sada metrik a~iterativní postup; konkrétní
naměřené hodnoty jsou vázány na podmínky případové studie.
}
\def\AbstraktEN{%
AI coding agents can generate functional code, but without proper instructions
they fail to follow software engineering practices. Existing benchmarks measure
only the outcome (did the agent solve the task?), not process quality or code
quality. A~formalized process for designing and evaluating instructions is
still lacking.
%
This thesis pursues three goals: (1)~design a~metric suite measuring agent
process, quality, and efficiency; (2)~demonstrate an iterative instruction
design process driven by these metrics; (3)~use ablation to explore which
instruction components contribute to the observed behavior and which are
redundant.
%
The metric suite and process are evaluated on a~single case study of
a~dunning system. The agent (MiniMax-M2.5 model via the OpenCode tool)
underwent five pilot iterations and two ablations, each evaluated in two
independent runs. Behavior was measured
using 19~metrics in three categories: process~(P), product~(Q), and
efficiency~(E).
%
The metrics showed that iterative instruction changes improved workflow
adherence, but not monotonically. The best pilot run achieved full
compliance on process metrics P1--P5 and increased reference-test
performance from 39/42 to 41/42. Analysis revealed an instruction
evolution pattern: general rule $\to$ specific command $\to$ verification
step. Ablation showed that verification steps are not redundant:
removing them degraded both functional correctness and automated code-quality
metrics. The code-convention section proved largely redundant for automated
metrics, but it still affected design quality as assessed by an
LLM-as-judge. The results also showed that process compliance is highly
sensitive to model non-determinism.
%
The transferable contributions are the metric suite and the iterative process;
the specific measured values are bound to the case study conditions.
}
